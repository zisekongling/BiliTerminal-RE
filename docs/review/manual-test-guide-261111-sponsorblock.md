> L0 已过：`:app:assembleDebug` BUILD SUCCESSFUL；`:app:testStandardDebugUnitTest` 新增两套纯函数单测共 26 例（`SponsorSkipPolicyTest` 17 例、`SponsorBlockApiTest` 9 例），`failures="0" errors="0"`（26.11.11 本机实测）。26.11.14 又加 `SponsorIgnoreTest` 11 例，全仓 1220 tests / 0 failures。
> 预计 18 分钟；**需要一个能出网的设备**（要对 `bsbsb.top` 发一次 HTTPS 请求），不需要登录 B 站。

## 这次加的是什么（先理解再看画面）

数据来自第三方志愿者标注服务 BilibiliSponsorBlock：观众手工标出「哪一段是恰饭广告 / 三连提醒 / 片头」，播放器拿到这些区间后像自动跳过片头片尾一样自动 seek 过去，屏幕下方留「不准」。它**不是 B 站官方数据**，只覆盖标注过的视频（绝大多数视频没有标注，那样就什么都不会发生，也不会报错）。26.11.14 起，会被跳过的片段还会在进度条底边画成琥珀色细条。

档位（设置 → 视频播放器 → **自动跳过** 分组里的「跳过广告片段（SponsorBlock）」，默认**关闭**；「自动跳过片头片尾」同组）：

| 档位 | 会跳的类别 |
| --- | --- |
| 关闭 | 什么都不查（**一个请求都不发**） |
| 仅恰饭广告 | `sponsor` |
| 广告 + 自我推广 | 上面 + `selfpromo` |
| 推荐（默认推荐档） | 上面 + `interaction` / `intro` / `outro` |
| 全部类别 | 上面 + `preview` / `filler` / `music_offtopic` / `exclusive_access` / `chapter` |
| 自定义 | 由同组「要跳的类别」子页里勾的那些决定（默认勾的就是「推荐」那五类） |

`poi_highlight`（精彩时刻）**任何档位都不跳**——它是跳转点，不是一段广告。静音型（`mute`）本版不处理；整段视频标签（`full`）自 26.11.14 起只在一 P 加载好时提示一次「本片整片都是……」（见 S09），跳不了也不改变别的片段的行为。

## 判据

- **该跳的跳、不该跳的不跳**是主要判据；提示文案里的类别名必须是中文。
- 只要出现「跳完后又弹回去」「同一段反复跳」「无标注的视频也弹提示」，就是 `sponsorDecider` 的 handled / 撤回判定出了问题，先看 `SponsorSkipPolicy.buildSegments` 的区间过滤与 `SkipDecider.applyLoaded` 的 `segmentsChanged` 语义，别先怀疑网络。
- 「跳完弹幕空白」属于弹幕链的问题（`DanmakuStreamLoader`），不是这个功能引入的，但要记下来，因为 seek 走的是同一条 `seekToPosition`。
