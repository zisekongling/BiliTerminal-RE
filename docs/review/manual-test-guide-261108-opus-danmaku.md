# 26.11.08 专栏段落富文本与弹幕下载失败语义 · 人工验收单（6 条，约 15 分钟）

- 安装包：`app/build/outputs/apk/standard/debug/app-standard-universal-debug.apk`（共存版同路径的 `coexist` 目录，二者代码相同）
- 版本：`versionName 26.11.07` / 对应 commit `c37258d`（段落里的 @ 与链接可点）与 `39e4136`（弹幕下载补 HTTP 状态码校验）；弹幕那条 26.11.08 又由 `b2be26f` 把漏掉的下载服务副本（`DownloadService.downDanmaku`）收口到同一实现，失败语义不变
- 前置：**不需要登录**（@ 与链接游客态就能点，用户主页也能看）；H05 / H06 需要设备上已经有 1 个缓存好的视频（主菜单 → 缓存 → 任一视频，任意清晰度即可）
- 设备形态：手表圆屏优先（点的准不准在手表上才判得出来）；手机方屏可验跳转对不对，但「长段落里点得准不准」建议在手表上判
- 回结果：通过写 `- [x]`；不通过留空，并在旁边写一句「看到的是什么」

> 这一批改的是两件不相干的事：①专栏 / 动态正文「段落里」的 `@某某` 与网页链接以前只是普通黑字、点不动，现在按链接色渲染并且能点；②弹幕下载以前不判 HTTP 状态码，失效地址回 404/412 的错误页会被当成弹幕存进 `danmaku.xml`，表现成「下载成功但播放时没弹幕」，现在一律当失败处理。

## H01 段落里的 `@某某` 点得动，且进的是对的人

- **怎么做**：找一个正文**段落里**带 `@某某` 的专栏或动态（图文里一般也带），点开它；在正文里找到那句 `@某某`，点一下；返回后再点同一个人名一次。找不到合适内容时，可以问技术同学给一篇现成的链接。
- **应该看到**：①`@某某` 显示成**链接色**（跟随当前主题的链接色，不加下划线），与正文的普通黑/白字明显不同；②点它进的是**这个人的用户主页**（顶栏标题是「用户信息」，页面上是这个人的昵称、头像、动态），不是搜索页、不是文章页；③返回后再点一次仍然进同一个人。
- **不算 bug**：游客态点进去看到的是「未登录」的用户主页（关注/私信按钮不出现），这是正常的；`@` 与名字之间带空格、或者服务端下发的是「@」+ 空 mid 时点了没反应，属服务端数据问题，不算本单的问题。
- **AI 断言**：`adb logcat -d | grep -i "UserInfoActivity"` 能看到目标页被拉起；更硬的判据是 `adb shell dumpsys activity activities | grep -i "UserInfoActivity"` 里有该页、且 Intent 里 `mid` 非 0。人判：链接色是否显眼但不刺眼。
- **预计**：2 分钟

## H02 段落里的链接点到的是「真地址」，不是那截被缩短的显示文字

- **怎么做**：找一篇正文里带网页链接的专栏（服务端常把显示文字缩短成 `av1`、`BV…` 这类），依次点：①带 `bilibili.com/video/BV…` 的链接；②显示成 `av1` 这种「短得不像真地址」的链接；③`b23.tv/…` 短链；④`/opus/数字` 形式的链接（有的话）。每点一次都返回，再点下一个。
- **应该看到**：①进的是那个 BV 号对应的**视频详情页**；②进的是**这篇专栏真正想指的**那篇视频，**不是** aid=1 的那篇站内古董视频（旧实现拿显示文字当地址，点 `av1` 就会跑到 aid=1 去）；③短链先跟随跳转、落到成片页（视频 / 专栏 / 动态其中之一），不白屏；④进的是那篇专栏详情页。四种情况都**不应该**出现「打不开浏览器」「跳去系统浏览器」。
- **不算 bug**：链接显示的文字可能和它指的内容看起来对不上（例如显示 `av1`、打开的却是另一篇）——服务端给的就是一个缩短的显示文本，点击用的是真实地址，这是刻意的；站外链接（非 bilibili.com）会交给系统浏览器 / 站内打开逻辑，属既有行为。
- **AI 断言**：点击后 `adb shell dumpsys activity activities | grep -E "VideoInfoActivity|OpusInfoActivity|DynamicInfoActivity"` 能读到目标页，且 Intent extras 里的 `bvid` / `aid` / `id` 与链接一致（可以先 `adb shell dumpsys activity top` 看）。人判：短链跟随过程中有没有卡住、有没有闪一下白屏。
- **预计**：3 分钟

## H03 长段落里文字、表情、@、链接混在一起时，点哪算哪

- **怎么做**：找一段**长正文**，里面有表情（`[大笑]` 之类的图片）、`@某个人`、链接和普通文字混排。依次试：①点在某个字上（非链接）；②点在表情图上；③点在 `@` 与名字之间；④按住正文不放 2 秒再松手；⑤手指从链接上按下、滑到旁边再松手。
- **应该看到**：①点普通文字没有任何跳转（不误触）；②点表情图不跳转；③点在 `@` 与名字之间——落在 `@某某` 这段范围内才跳，落在外面不跳；④长按 2 秒进的是「复制 / 操作」页（长按复制的既有行为），**不会**同时跳链接；⑤按下后滑走的这次手势不算点击，不跳转。
- **不算 bug**：「设置 → 内容与浏览 → 通用偏好 → 识别链接」如果被关掉，正文里的**链接和 @ 都点不动**（两者共用同一套点击处理）——验收时请确认这个开关是**开**（默认开），否则本单会被误判成失败。表情是图片，没有「可点」的含义，点它没反应是预期；「长按复制」也可以在「设置 → 内容与浏览 → 通用偏好 → 长按复制」里关掉，关掉后长按不再弹复制页（也不算 bug）。
- **AI 判不了**：点击位置是否落在正确的词上、长按与点击会不会互相抢，只能手指判；dump 里也看不到 span 的边界。
- **预计**：3 分钟

## H04 链接色与正文的观感：能看出「这里能点」，但不抢正文

- **怎么做**：在暗色和亮色两种模式下（设置 → 界面与外观 → 外观设置 → 颜色模式）各看一篇带 `@`、链接、话题的专栏；再换一套主题配色（例如默认终端 ↔ 哔哩粉）看一遍。
- **应该看到**：`@某某` 与网页链接用的是**主题链接色**（`ColorScheme` 的 `LINK`），`#话题#` 用的是**主题主色**（`PRIMARY`）——两者本来就不是同一个颜色，这是既有口径，不是本批改的；两类都**没有下划线**。它们都能在正文里一眼认出来，但读长文时不刺眼；亮色模式下不发白、暗色模式下不发黑；正文其余部分仍是主题的文字色（亮色下是深色字，不是白字）。
- **不算 bug**：话题（主色）和链接（链接色）颜色不同是刻意的；某些主题里这两个色本来就接近，看不出区别不算 bug；换主题后颜色跟着变（跟随主题取色，不硬编码）；部分专栏自带的文字颜色本来就不显示（已知限制）。
- **AI 判不了**：颜色对比与「刺不刺眼」只能人眼判，截图在手表上也不可靠。
- **预计**：2 分钟

## H05 弹幕下载失败时要明确报失败，而不是「成功但播放时没弹幕」

- **怎么做**：
  1. 主菜单 → 缓存，确认里面有一个已缓存好的视频；**先联网**长按它 → 点「更新弹幕」——应看到「弹幕更新成功」；进播放页确认弹幕能滚出来（这就是 H06）。
  2. 退出播放页，回缓存页；把 Wi-Fi 与移动数据**都关掉**（或开飞行模式）；再长按同一个视频 → 「更新弹幕」。
  3. 看到结果后，重新联网，进播放页看弹幕是否还在（应该还在——失败的那次不该把已有弹幕清掉）。
- **应该看到**：步骤 2 之后给出**明确的失败提示**（缓存页上是「弹幕更新失败：<原因>」，原因里可能带 `HTTP 404` / `HTTP 412` / 超时之类的字样），**不出现**「弹幕更新成功」；批量更新（多选 → 批量操作 → 更新弹幕）在断网下给出「弹幕更新完成：成功 0 个，失败 N 个」这样的统计，而不是笼统说成功；步骤 3 里原有弹幕仍然能正常显示，没有被空文件覆盖掉。
- **不算 bug**：断网时的原因文案是网络异常（超时 / 无法连接），不是 HTTP 状态码，这是正常的——只有服务端真的回了 404/412 才会出现「HTTP 4xx」。合集类视频里只要有一页失败，整条都会算失败（它们共用同一次更新的结果）。「弹幕地址获取失败」是另一种情况（接口根本没给地址），与本次修的「地址失效」不是同一句提示。
- **AI 断言**：断网失败后 `adb logcat -d | grep "弹幕下载失败"` 应能读到异常原文（`DanmakuFileFetcher` 抛的那句）；正常成功时 `danmaku.xml` 的首段应是 `<?xml` 而不是 HTML 错误页（技术同学可以用调试桥取文件核对）。人判：提示出现得及不及时、看不看得清。真正的 404/412 场景要用一个必然失效的地址才能造出来——那一步由技术同学用调试桥 / 单测覆盖，不必你手工造。
- **预计**：3 分钟

## H06 成功路径没被误伤：正常「更新弹幕」之后弹幕照常显示

- **怎么做**：联网状态下，对一个**正常视频**的缓存长按 → 「更新弹幕」→ 提示成功后进播放页，看 30 秒；再试一个**多 P（分集）**的缓存（如果手边有），进第二 P 看弹幕。
- **应该看到**：「弹幕更新成功」；进播放页后弹幕在滚动、开/关弹幕键有效；多 P 视频每一 P 的弹幕都各自出现（不是只有第一 P 有）；反复更新两次不会把弹幕弄丢或叠成两份。
- **不算 bug**：冷门 / 新上传的视频本来就可能真的没有弹幕（此时弹幕区是空的，但不会报错）；弹幕多了会自动限流，滚动会变稀（既有保护）。
- **AI 断言**：`adb logcat -d | grep -E "弹幕|danmaku"` 里不应出现 `弹幕下载失败`；`prepareDanmaku` / `loadFromXmlFile` 相关日志正常出现。人判：弹幕是否真的在画面上滚。
- **预计**：2 分钟
