## H18 模式「仅视频详情页」：普通页面长按顶栏不震、也不动作

**改的是什么**：模式不允许时监听器仍然 `return true` 把手势吞掉（防止回落成一次单击退出页面），而 `View.performLongClick()` 只要回调返回 true 就无条件 `performHapticFeedback(LONG_PRESS)` —— 「什么都不做」也照样震一下。本次改成在 `onStart` 按本页判据同步 `topBar.isHapticFeedbackEnabled`，让框架自己不去震。

1. 设置 → 长按顶部标题栏 → 选「**仅视频详情页**」，返回。
2. 在首页 / 推荐 / 动态 / 我的任一普通页面，长按顶栏标题（按住约 0.5 秒以上，**别松手太快**）3~5 次。
   - [ ] 全程**没有震动**。
   - [ ] 也不弹出菜单列表、页面不退出（这一条改前就是这样，本次没动）。
3. 手指按住顶栏后小幅移动再松开（同一个长按的另一种走法），同样不震。

**应该看到**：只在「仅视频详情页」这一档、普通页面上，长按顶栏既无动作也无震动，页面停在原地。
**不算 bug**：手势要按住够久才判定成长按，指尖别抖开；侧键 / 系统返回手势截胡不算。
**预计**：3~5 分钟。
**AI 半自动**：动作部分（是否弹菜单 / 是否退出）可用 `adb` 日志与控件树佐证，震动只能人判。

## H19 模式「仅视频详情页」：视频详情页长按仍关闭所有详情页**且保留震动**

**改的是什么**：震动开关按「本页是否真的执行动作」来同步（`handlesTopbarLongPress()` 为 true 走视频页判据 `mode() != MODE_OFF`），这一档视频页是「允许」的，所以震动必须**还在**——这是本次最容易改坏的地方（一旦把开关一律置 false，视频页就静默不震了）。

1. 保持「仅视频详情页」不变，从首页进任意视频详情页（点视频进去，或播放页返回详情层）。
2. 长按顶栏 2~3 次。
   - [ ] 每次都能**关闭所有详情页**回到上一层（动作与改前一致）。
   - [ ] 每次都**有震动**（与改前一致）。
3. 在同一档下把「长按顶部标题栏」先改成「不响应」再改回「仅视频详情页」，重复第 2 步：结果不变（设置改完回页面即生效，不用重进应用）。

**应该看到**：视频详情页的动作与震动两样都在。
**不算 bug**：详情页只有一层时「关闭所有详情页」的表现就是返回上一层。
**预计**：3 分钟。
**AI 判不了**（震动）。

## H20 模式「不响应」：普通页面与视频详情页都无动作、无震动

1. 设置 → 长按顶部标题栏 → 选「**不响应**」。
2. 普通页面长按顶栏 3 次。
   - [ ] 不弹菜单、不退出、**不震动**。
3. 进视频详情页长按顶栏 3 次。
   - [ ] 不关闭详情页、**不震动**。
4. **重点复核**：若这一档下**仍然有震动**，说明那一下不是 `View.performLongClick` 发出来的（可能是系统长按手势 / ROM 自己补的震动），本修的开关管不到——把机型与系统版本报回来，不要自己改代码。

**预计**：2 分钟。
**AI 判不了**（震动）。

## H21 模式「全部页面」（默认，旧行为）：两处都仍有动作 + 震动

1. 设置 → 长按顶部标题栏 → 选「**全部页面**」（这也是默认档）。
2. 普通页面长按顶栏：弹出菜单列表 + 震动（与 26.11.07 一致）。
3. 视频详情页长按顶栏：关闭所有详情页 + 震动（与改前一致）。
4. 顺手回归：双击顶栏进伪装页照旧（开关打开时）；单击顶栏仍是「返回上一页 / 打开菜单」；开启伪装时长按走的是 `DisguiseGesture` 的 `topBar.performLongClick()` 回放，与上面各档结论应一致。

**应该看到**：默认档与改前完全一致，没有任何手感变化。
**不算 bug**：圆屏 / 方屏只影响顶栏位置；暗号错误等其他伪装问题不在本单范围。
**预计**：3 分钟。
**AI 判不了**（震动）。
