## Background

GitHub issue #35：Android 4.4 手表上一联网就崩。

不是偶发、也不是某个页面的问题，是**依赖在类初始化阶段主动拒绝低版本**：
`okhttp3.internal.platform.AndroidPlatform.<clinit>` 里 `if (Platform.isAndroid && Build.VERSION.SDK_INT < 21) throw IllegalStateException("Expected Android API level 21+ but was " + SDK_INT)`
（d8 反汇编 `app/libs` 里的 okhttp 4.12.0：`041506 const-string` / `041522 new-instance` / `041534 throw`）。
初始化失败后，之后**每一次** OkHttp 调用都是 `NoClassDefFoundError: okhttp3/internal/platform/Platform`。

关键历史事实：`app/build.gradle` 的 `implementation 'com.squareup.okhttp3:okhttp:4.12.0'` 自 2026-10-30 `a7fb06be` 就在（`git log -S` 唯一命中），
而 `minSdk 19` 是 26.10.10 才落的 ⇒ **19 这段从来没有一个版本在 4.4 上真跑通过**，issue #35 是第一次真机暴露。

用户决策（26.11.21）：**暂时改成 5.0（minSdk 21），等期中考试结束后再恢复**；先回 issue。

- 依赖侧连带评估：`appcompat 1.6.1 → 1.7.0`、`fragment-ktx 1.6.2 → 1.8.0`（AAR 自身 minSdk 21，必须 minSdk 回到 19 之前先解决这层矛盾）、`multidex` 是否真要保留。

## Process

- 根因证据是字节码级，不是推测：okhttp 4.12.0 的 `AndroidPlatform.<clinit>` 三条指令（`041506`/`041522`/`041534`）直接对应 `throw IllegalStateException("Expected Android API level 21+ but was …")`。
- 降级可行性已核实：okhttp **3.12.13** 的 `AndroidPlatform.buildIfSupported` 只判 `Platform.isAndroid` + `Class.forName("com.android.org.conscrypt.SSLParametersImpl")`（失败再试 harmony 那套），**没有 SDK<21 的抛错**；3.12.13 的 dex 里 `peekBody`、`callTimeout` 都存在，调用面不会缺方法。
- 改造面已核数：okhttp4 Kotlin 属性写法 **125 处 / 57 个 .kt 文件**；Java 文件 0 改动（4.x 保留了 Java 可见方法名 `.body()` / `.code()`）；4.x 专属 API 只有 `util/UpdateManager.kt:15/18/230` 三处。
- okio 不是障碍：直接引用仅 5 处，全部是 okio 1.15 也有的 `BufferedSource` / `Buffer` / `ByteString.of|hex|toByteArray`（`NetWorkUtil.java:565/567/1096`、`TestActivity.kt:26`、`PlayerDanmuClientListener.kt:11/85/89/93/99/143/149`）。
- R8 已兜住：proguard 是整包 `-keep class okhttp3.** { *; }` + `-dontwarn okhttp3.**` / `-dontwarn okio.**`。
- 风险（恢复时逐条对）：① okhttp 3.x 已 EOL，无安全更新；② 4.4 上 TLS 1.2 要靠 OkHttp 反射开启，小天才一类 ROM 可能握手失败，只能真机验；③ WebSocket / 流式下载行为差异编译期看不出；④ 以后再回 4.x/5.x 要再改一遍 125 处。
- 本机验证条件：`D:\Program Files\android-sdk` 下无 `system-images`、无 AVD、`adb devices` 空——4.4 相关只能静态审计 + 人测。
- 本轮（暂时回 21）刻意**只动 minSdk 一行**：`appcompat`/`fragment-ktx` 的降级钉子与 `multidex` 依赖都保留，避免和恢复 4.4 那轮互相冲突（升 appcompat 会牵动主题与控件行为）。
