# 新功能测试手册（26.11.06 测试版 · 人机双轨）

> **这份手册是给谁看的**：两条轨道。**人**——不用懂代码、不用看日志，会点屏幕就能一条条测；
> **AI**——凡是「结论能从日志/控件树里读出来」的，都写成了可直接抄的断言，不必再问人。
> **它测什么**：26.11.06 这一轮从兄弟分支移植过来的新功能，加上顺手修的几个毛病。
> **怎么用**：人从「开始之前」往下做，每条在 `- [ ]` 里打勾；AI 先看「§0 AI 怎么跑」，再只跑标了 `AI 断言` 的条目。

## 开始之前

**要准备的东西：**

1. 一台装了 26.11.06 测试包的设备（手表优先，手机也行）。装之前建议先卸载旧版，避免旧设置干扰。
2. 一个能正常登录的 B 站账号（第二、三部分要用；第一部分不用登录）。
3. 能上网的 Wi-Fi；第三部分有两条需要**关掉 Wi-Fi 用移动数据**。
4. 一副能连手机的蓝牙耳机（可选，只有一条要用）。
5. 一张自己手机相册里的普通照片（只有「背景图」那条要用）。

**记结果的方式：**

- 通过：在方框里打 `x`，写成 `- [x]`。
- 不通过：方框留空，在旁边写一句「看到的是什么」，比如「点了没反应」「直接退回上一页」「数字没变」。
- 拿不准：写「不确定」，并说明哪里不确定。

**三条通用提醒（省得白测）：**

1. **设置类改动很多是「下次进入才生效」**，不是点完立刻变。每条都写了要退出再进，别急着判失败。
2. **第一次进某个页面慢一点是正常的**，尤其是老手表；等 3 秒还没反应才算有问题。
3. **网络不好会误伤**：所有「加载不出来」的问题，先换 Wi-Fi 或等网络稳定再复测一次，还是不行才算不通过。

## §0 AI 怎么跑（Human 可跳过）

AI 不许靠看截图猜结论（`docs/agents/testing.md` §4），但**提示文案、设置值、控件树文字、日志、落盘文件**都能读。
先把三条命令定义清楚，后面每条断言都直接引用：

```bash
PKG=com.RobinNotBad.BiliClient.coexist            # 普通版改成 com.RobinNotBad.BiliClient
BRIDGE=$PKG/com.RobinNotBad.BiliClient.debug.DebugBridge
bridge() { adb shell am broadcast -n "$BRIDGE" --es token rebili-agent-bridge "$@"; }

bridge --es cmd ping                               # ① 健康检查：版本 / logi / logToFile / top
bridge --es cmd agent --ez on true                 # ② 开 Agent 模式：日志全量 + 落盘 + HTTP 追踪
adb logcat -c                                      # ③ 每条用例开跑前清一次屏
```

跑完一条，取证只看三种东西：

```bash
adb logcat -d -s "MsgUtil>showMsg"                 # 提示原文（showMsgLong 另用 MsgUtil>showMsgLong）
adb shell uiautomator dump --compressed /sdcard/u.xml && adb shell cat /sdcard/u.xml   # 控件树文字
bridge --es cmd log --es file rebili.log --es bytes 8192                                # 落盘日志尾部
```

**四条硬规矩**（都是踩过的坑，别再试）：

1. **`Logu.i` 只在 `LOGI_ENABLED` 为真时才输出**（Debug 包默认开；被关过就 `bridge --es cmd set --es key dev_logi --es value true`，`set` 会立刻 `applyLogSwitches`，不必重启）。提示断言抓不到东西，九成是这一条。
2. **`MsgUtil.showMsg` 的 logcat tag 恒为 `MsgUtil>showMsg`，消息正文就是提示原文**——一字不差（含标点）。文案改了断言就该失效，这正是它在检查的东西。
3. **`bridge --es cmd start` 回 `OK` 不代表到了目标页**，必须再 `bridge --es cmd top` 复核（`docs/review/agent-test-guide.md:161`）。
4. **装包后先核对版本**，别测到设备上的旧包：`adb shell dumpsys package $PKG | grep -i versionName`。

**这一轮 AI 能独立跑完 7 条**：T04 T05 T17 T19 T23 T26 T27。
**14 条只能验一半**（设置值/文案能断言，画面和手感要人）：T01 T02 T03 T06 T09 T10 T11 T13 T15 T20 T24 T31 T32 T33。
**13 条必须人做**（要真实账号写操作、中文输入、蓝牙/来电/切网、或纯画面）：T07 T08 T12 T14 T16 T18 T21 T22 T25 T28 T29 T30 T34。

> 每条用例末尾的 `AI 断言` / `AI 半自动` / `AI 判不了` 就是给 AI 的活；人只需要跑完自己那部分。

## 第一部分：不用登录就能测（约 25 分钟）

### T01 推荐页能一直往下翻

- **怎么做**：打开 App → 进「推荐」→ 手指一直往上滑，滑过 5～6 屏。
- **应该看到**：内容不断追加，能一直往下看；不会出现「同一批视频反复出现」；滑到底不会卡住不动。
- **不算 bug**：偶尔一条视频在很后面又出现一次（服务端重推），只要不是连着重复就不算。
- **AI 半自动**：滑 3 屏，每屏 `uiautomator dump` 取列表文字，比对新出现的标题/bvid 数量是否递增（判定「在加载」）；「同一批反复出现」「滑到底卡住」要人看。

### T02 换一张背景图

- **怎么做**：设置 → 界面与外观 → 外观设置 → 找到「背景图」→ 点「选择背景图」→ 从相册挑一张 → 退回上一页 → 再随便进几个页面。
- **应该看到**：所有页面背景都变成这张图；退出 App 再进还在；「适配方式」切「填满（裁切边缘）/ 适应（显示全图，留底色）」后画面跟着变；「遮罩强度」切「不遮罩 / 75%」时，75% 下卡片和字更清楚。
- **再试清除**：点「清除背景图」→ 背景恢复成原来的纯色。
- **AI 半自动**：`bridge --es cmd get --es key appearance_background_path` 应为非空路径；切适配方式后 `appearance_background_fit` 变、切遮罩后 `appearance_background_scrim` 变；清除后 `appearance_background_path` 为空。「背景真的变成这张图 / 75% 下更清楚 / 回纯色」只能人看。

### T03 光晕和背景图能同时开

- **怎么做**：接着上一条（背景图别清掉）→ 外观设置里打开「弥散光晕」→ 退出再进来。
- **应该看到**：屏幕边缘/顶部有一层淡淡的主题色光，**同时背景图还在**（不是变成纯色，也不是完全看不到光）。
- **反过来**：关掉光晕 → 背景图仍然在。
- **AI 半自动**：`get ui_ambient_glow` 为 `true` 且 `appearance_background_path` 仍非空（验「两个开关并存、互不清除」）；「真的同时看得见光晕和背景图」只能人看。

### T04 播放器设置页多出来的几项

- **怎么做**：设置 → 播放器 → 长按「内置播放器」那张卡片 → 进入内置播放器设置，往下翻。
- **应该看到**这几项，并且点了能改、退出再进来还是刚才选的：
  - 「长按上下划切换视频」（默认开）
  - 「长按倍速提示尺寸」（默认 100%，可选 80/100/120/150%）
  - 「本人弹幕边框」（默认开）
  - 「自动跳过片头片尾」：点进去是五个选项——关闭 / 仅片头 / 仅片尾 / 片头+片尾 / 询问我
  - 「弹幕缓存上限」（默认 64 MB，可选 关闭 / 16 / 32 / 64 / 128 MB）
- **AI 断言**：`bridge --es cmd dump` 里应出现这五个键，值与上面括号里的默认值逐条相符：
  `player_longpress_switch`、`player_longpress_hint_scale`、`player_danmaku_self_border`、
  `player_skip_op_ed_mode`、`player_danmaku_cache_max_mb`；再把某一项 `set` 成别的值、重进页面 `dump` 一次，值不变即为「退出再进还记得」。

### T05 存储空间页

- **怎么做**：设置 → 缓存与下载 → 存储路径 → 点「存储空间」。
- **应该看到**：图片缓存、临时文件、更新安装包、可用空间四个数字；三个清理按钮。
- **试一下**：点「清理图片缓存」——没东西可清时应该提示「没有需要清理的内容」；有东西时先问一句再清，清完数字变小。
- **注意**：这一页只清图片缓存和临时文件，**不会动你下载的视频**。清完视频还在就是对的。
- **AI 断言**：先 `adb logcat -c`，再点「清理图片缓存」，`adb logcat -d -s "MsgUtil>showMsg"` 应出现原文
  「没有需要清理的内容」（缓存已空时）；页面文字用 `uiautomator dump` 应能搜到「图片缓存」「临时文件」「更新安装包」
  「可用空间」。清完「下载的视频还在」由人确认（AI 不碰用户缓存目录）。

### T06 清晰度能按 Wi-Fi / 移动数据分开设

- **怎么做**：设置 → 播放器 → 下方的「清晰度设置」。
- **应该看到**：除了原来的清晰度列表，多出「Wi-Fi 默认清晰度」和「移动数据默认清晰度」两行，都能选「跟随默认 / 360P / 720P…」。
- **试一下**：把 Wi-Fi 那行选成 720P，返回后该行显示「当前：720P」。
- **真正生效要等第三部分 T28**（要切换网络才能看出来）。
- **AI 断言**：把 Wi-Fi 那行改成 720P 后，`bridge --es cmd get --es key play_qn_wifi` 应为 `720`（移动数据同理 `play_qn_mobile`）；
  页面 `uiautomator dump` 应能搜到「当前：720P」。「真的按网络分档起播」归 T28，由人判。

### T07 看一张很长的图

- **怎么做**：找一条带长图/条漫的图文动态（或评论区里的长截图）→ 点图放大 → 上下拖动看。
- **应该看到**：能正常放大、能拖动看完，不白屏、不闪退、不卡死。
- **不算 bug**：放到最大时边缘有点糊，这是为了省内存故意降的清晰度。
- **AI 判不了**：白屏、糊、拖动跟手都是画面问题；AI 只看得到控件树文字，看不到图。唯一能替代的机器证据是「进程没崩」（`bridge --es cmd crash` 无关；崩溃看 `bridge --es cmd logring` 与 logcat 的 `FATAL`），不足以判通过。

### T08 设置搜索能搜到新功能

- **怎么做**：设置首页的搜索框，分别搜「背景图」「本人弹幕边框」「弹幕缓存」。
- **应该看到**：都能搜到对应条目，点一下能直接跳到那个设置项。
- **AI 判不了**：要往输入框里打中文，`adb shell input text` 只认 ASCII（装 ADBKeyboard 才能打中文，为一条用例不值当）。人 30 秒做完，AI 要先装输入法、切 IME、还得处理厂商 ROM 的 IME 弹窗。

## 第二部分：登录后测（约 40 分钟）

> 这一部分都要先登录。登录后如果提示「登录凭证已失效」，重新登录一次再继续。

### T09 连播队列（播放页多了个「连播」按钮）

- **怎么做**：打开一个多 P 视频（比如赛事回放、番剧合集）→ 进播放页 → 控制栏里找「连播」按钮 → 点它。
- **应该看到**：弹出四个模式：顺序 / 倒序 / 随机 / 单曲。
- **试一下**：选「顺序」→ 让它播完 → 自动进下一个；选「单曲」→ 播完重复当前这一条。
- **再试一下**：退出播放页再回来，模式还是刚才选的那档。
- **AI 半自动**：点开按钮后 `uiautomator dump` 应能搜到「顺序」「倒序」「随机」「单曲」四个文字；选完之后
  `bridge --es cmd get --es key player_play_queue_mode` 应等于所选模式（这就是「退出再回来还记得」的落点）；
  队列加载过程另有 `连播队列` 标签的日志（如「UP 主投稿队列已载入：N 项」）。「播完真的自动进下一条」要人看。

### T10 主菜单的「继续播放」

- **怎么做**：随便看一个视频，看到 30 秒以上 → 退出播放页 → 回到主菜单。
- **应该看到**：主菜单最上面多出一项「继续播放」。
- **点它**：从上次退出的位置接着播（差几秒是正常的）。
- **不算 bug**：看的不足 5 秒、或者超过 7 天没看，这项就不出现——这是故意的。
- **AI 半自动**：主菜单 `uiautomator dump` 应能搜到「继续播放」；点它之后 `bridge --es cmd top` 应落在播放器页；
  续播位置看日志 `继续播放` 标签（`aid=` / `cid=` / `progress=`）。「差几秒」的人体感受归人。

### T11 自己发的弹幕有边框

- **怎么做**：播放一个视频 → 发一条弹幕 → 等它出现在屏幕上（或者退出重进这个视频）。
- **应该看到**：自己发的那条弹幕外面有一圈主题色边框，别人的没有。
- **再试一下**：去设置里把「本人弹幕边框」关掉 → 重新进视频 → 自己的弹幕没有边框了。
- **不算 bug**：未登录、或者这条弹幕是匿名/认不出是谁发的，就不会有边框。
- **AI 半自动**：`get player_danmaku_self_border` 能验开关本身与「关掉后仍是 off 且没把别的设置带坏」；
  **边框是画在 Canvas 上的，控件树里读不到**，有没有那圈主题色只能人看。⚠️ 别用截图判颜色：MuMu 的
  `screencap -d <display>` 对本应用的活动副屏恒返回 `Status: -2`（`docs/review/agent-test-guide.md:373`）。

### T12 点带时间的弹幕能跳进度

- **怎么做**：找一个弹幕里有人发「01:23」这种时间的视频 → 在画面上点那条弹幕。
- **应该看到**：进度直接跳到 01:23。
- **不算 bug**：点「1080P」「1:2」「99:99」这类不是时间的弹幕，什么都不会发生。
- **AI 判不了**：弹幕是移动的，AI 拿不到它的实时坐标（控件树里根本没有弹幕节点），点不中就什么都证明不了。人一眼能看出跳没跳。

### T13 片头片尾的五档设置

- **怎么做**：打开一集有片头/片尾的番剧 → 设置里把「自动跳过片头片尾」选成「询问我」→ 从头播，等播到片头快结束。
- **应该看到**：弹一次确认框问你要不要跳过；**你不点它就不会跳**；同一集只问一次。
- **再试**：改成「片头+片尾」→ 自动跳过去，屏幕下方留一个「撤回」，点一下回到跳之前的位置。
- **AI 半自动**：`get player_skip_op_ed_mode` 能验五档的值确实写进去了；询问框与「撤回」按钮的文字能在
  `uiautomator dump` 里搜到（有 = 出现了）；跳过动作本身看 `MsgUtil>showMsg` 的「已开启自动跳过片头片尾」与播放进度日志。
  「同一集只问一次」「撤回回到原位」要人判。

### T14 番剧每集进度

- **怎么做**：看番剧第 2 集，看到一半退出 → 再从番剧页点进第 2 集。
- **应该看到**：从上次的位置接着播，不是从 0 开始。
- **注意**：第 3 集应该是从头播，别把「每集各记各的」当成 bug。
- **AI 判不了**：进度是服务端记的（`x/player/report`），本地只能证明「上报请求发出去了」，证明不了「服务端记的是第 2 集的位置」。要么人看，要么用两个设备跨端复核——那已经不是一条用例的成本。

### T15 评论加载更稳

- **怎么做**：打开一个评论很多的视频 → 进评论区 → 来回切页、连续下拉刷新几次。
- **应该看到**：评论正常加载，不重复出现同一条，不闪退，也不会突然变成空白。
- **AI 半自动**：切页/刷新后 `adb logcat -d` 里不应出现 `FATAL`、`E/AndroidRuntime`，`http.log` 里该接口不应是 4xx/5xx；
  `uiautomator dump` 的评论 rpid/正文不应整屏突然变空。「不重复出现同一条」需要人能记住刚才看过什么，但也能用
  dump 文本做重复统计——AI 可以做一半。

### T16 评论点赞/删除，返回列表也同步

- **怎么做**：在评论列表里点开某条评论的详情 → 给它点赞 → 返回列表。
- **应该看到**：列表里那一条也显示已赞（不用再点一次）。
- **再试**：删掉自己的一条评论 → 返回列表，那条应该消失。
- **AI 判不了**：这是**拿真实账号改真实数据**的写操作，删掉的评论找不回来。AI 不许拿用户账号当夹具
  （`docs/agents/testing.md` §3.2），这条只能人做。

### T17 回复评论时没有「加图」按钮

- **怎么做**：在评论区点「回复」某条评论（楼中楼）→ 看输入框旁边。
- **应该看到**：**没有**图片按钮。
- **对照**：发一条普通评论（不是回复别人）时，图片按钮在。
- **为什么**：B 站楼中楼本身不支持带图，以前是选完图才失败，现在直接不给入口。
- **AI 断言**（判定看「该在的地方有、不该在的地方没有」，不靠截图）：`bridge --es cmd start --es activity WriteReplyActivity`
  起两次——一次带 `root/parent`（回复模式）、一次不带（一级评论），各 `uiautomator dump` 一次；
  回复模式的树里搜不到「图片」这个控件，一级评论模式的树里能搜到，即为通过。
  代码依据：`app/src/main/java/com/RobinNotBad/BiliClient/activity/reply/WriteReplyActivity.kt:226-234`
  （非一级评论把 `imageEntry` 与 `imageText` 一起 `GONE`）。

### T18 收藏夹里能搜索

- **怎么做**：我的 → 收藏夹 → 进一个视频比较多的收藏夹 → 顶部筛选条里点「搜索收藏夹」→ 弹框里输入关键词（标题或 UP 名）→ 确定。
- **应该看到**：只显示匹配的视频；点「清除搜索」后恢复全部。
- **不算 bug**：搜不到时提示的是「没有匹配的收藏内容」，不是「收藏夹是空的」。
- **AI 判不了**：关键词得是中文（标题/UP 名），打字这一步 AI 过不去（见 T08）。但**预期文案已定死**，人要核对的就这两句：
  「没有匹配的收藏内容」（空结果）、「搜索：<关键词>」（生效中）。

### T19 「全部收藏」

- **怎么做**：我的 → 收藏夹（收藏夹列表页）。
- **应该看到**：列表里多出一项「全部收藏（最近）」→ 点进去是所有收藏夹的视频合在一起（按最近收藏排序），顶部还会写「共 N 条，来自 M 个收藏夹」。
- **不算 bug**：同一个视频同时收在两个夹里，会出现两次——这是合并的正常结果。
- **AI 断言**：`bridge --es cmd start --es activity FavoriteFolderListActivity` → `uiautomator dump` 应搜到「全部收藏（最近）」；
  进聚合页后再 dump 一次，应搜到「共 」+「条，来自 」+「个收藏夹」（完整格式是
  「共 N 条，来自 M 个收藏夹；K 个读取失败」，见 `app/src/main/res/values/favorite_port_strings.xml:28`）。
  「按最近收藏排序」要人判。

### T20 收藏夹批量下载

- **怎么做**：收藏夹里长按一条视频 → 菜单里选「多选」→ 勾几条（不超过 20 条）→ 点「下载」→ 选清晰度。
- **应该看到**：提示已加入下载；去下载列表能看到这些任务。
- **注意**：一次最多下载 20 条，多勾的会被跳过——弹窗里会写「另有 N 条…已跳过」。
- **AI 半自动**：`adb logcat -c` 后操作，`logcat -d -s "MsgUtil>showMsg"` 应出现「正在提交 N 条下载…」，勾了不支持/重复的条目时
  还要出现「另有 N 条不支持下载或重复，已跳过」；`bridge --es cmd start --es activity DownloadListActivity` 后 dump
  应能看到这些任务名。⚠️ **这一步会真的建下载任务、真的写用户存储**，只能在专用测试机上跑，且跑完人工清掉。

### T21 历史记录里能搜索

- **怎么做**：我的 → 历史记录 → 顶部筛选条里点「搜索记录」→ 弹框输入关键词（标题或 UP 名）→ 确定。
- **应该看到**：列表只剩匹配的记录，并且提示里写明了「仅在本页已加载的 N 条记录中搜索」。
- **不算 bug**：更早的历史搜不到——B 站没有给搜索接口，只能搜已经加载出来的。
- **AI 判不了**：同样是中文输入。人只需核一句话：「仅在本页已加载的 N 条记录中搜索」有没有如实显示
  （`app/src/main/res/values/favorite_port_strings.xml:55`）。

### T22 历史记录多选删除

- **怎么做**：历史记录里长按一条 → 菜单里选「多选删除」→ 在弹出的勾选面板里勾几条 → 点删除。
- **应该看到**：被勾的从列表消失；清掉搜索词后也不会「复活」。
- **AI 判不了**：删的是真实账号的观看记录，不可恢复。AI 不碰真实账号的删除（`docs/agents/testing.md` §3.2）。

### T23 动态卡片上的「评论」入口

- **怎么做**：主菜单进「动态」→ 看每条动态卡片底部的操作栏。
- **应该看到**：有一个「评论」和数字；点它直接进这条动态的评论。
- **不算 bug**：没有人评论的动态只显示「评论」两个字、没有数字，是正常的。
- **AI 断言**：`bridge --es cmd start --es activity DynamicActivity` → `uiautomator dump` 里第一张卡片的操作栏应搜到「评论」；
  点它之后 `bridge --es cmd top` 应变成评论页（`ReplyInfoActivity`）。有数字 vs 只有「评论」两个字两种情况都能在 dump 里区分。

### T24 定时发布的「自定义时间」

- **怎么做**：发动态 → 选定时发布 → 「自定义时间…」→ 输入一个时间。
- **应该看到**：
  - 输入「现在 + 3 分钟」→ 提示太早（要求至少 6 分钟后）；
  - 输入「现在 + 8 天」→ 提示太晚（最多 7 天）；
  - 输入合法时间（比如明天中午）→ 按钮上显示预定时间，能正常发出去。
- **AI 半自动**：`adb logcat -c`，输入太早/太晚的时间后点发送：
  `logcat -d -s "MsgUtil>showMsg"` 应分别出现原文
  「太早了：定时时间至少要在 6 分钟之后」与「太晚了：定时时间最多只能定到 7 天以内」
  （`app/src/main/java/com/RobinNotBad/BiliClient/activity/dynamic/send/SendDynamicActivity.kt:413-429`），
  **同时 `http.log` 不应新增任何请求行**（校验失败要在发请求之前返回）。「合法时间真的发出去了」要人判。
  时间输入框是纯数字，`adb shell input text` 打得进去。

### T25 私信能发表情

- **怎么做**：消息 → 打开一个私信对话 → 输入框旁边找表情按钮 → 点开面板 → 选一个表情。
- **应该看到**：表情插入到光标位置，发出去后对方（或自己这边）能看到表情图案。
- **AI 判不了**：要真的把私信发给真人（真实账号、真实对外发送）。AI 不许代发消息。

### T26 用户主页显示性别和 IP 属地

- **怎么做**：打开任意一个用户的主页。
- **应该看到**：昵称下方有性别和 IP 属地，形如 **「性别：男 · IP属地：广东」**（两个字段各带前缀，中间是一个「 · 」）。
- **不算 bug**：对方没公开或者 B 站没给这两项时，就不显示——不是 bug。
- **AI 断言**：`bridge --es cmd start --es activity UserInfoActivity --es extras "mid=<某个 mid>"` → `uiautomator dump`
  里应搜得到「性别：」和「IP属地：」两段文字；两项都缺的用户应两段都搜不到（不显示空标签）。
  格式来源：`app/src/main/res/values/social_port_strings.xml:15-18`（`性别：%1$s`、`IP属地：%1$s`、分隔符 `" · "`）。

### T27 关注/粉丝列表里的「互关」标记

- **怎么做**：我的 → 关注 或 粉丝 → 看列表里每个人。
- **应该看到**：互相关注的人旁边有「互关」标记；只有单向关注的人没有。
- **AI 断言**：`bridge --es cmd start --es activity FollowUsersActivity --es extras "mid=<我自己>"`（粉丝/分组同理）→ `uiautomator dump` 里「互关」
  出现的条数应等于列表里互关的人数；**看别人的关注列表时一个都不该出现**（代码只对自己的列表标，用同一次 dump 换个
  `mid` 再跑一次对比）。注意：徽章是列表复用控件，滚动后错位也算 bug——滚动两屏再 dump 一次比对。

## 第三部分：需要特别条件（约 20 分钟）

### T28 移动数据和 Wi-Fi 各用各的清晰度

- **前提**：手机上先设好——Wi-Fi 默认清晰度 = 720P，移动数据默认清晰度 = 360P。
- **怎么做**：连 Wi-Fi 播一个视频，看起播清晰度 → 关掉 Wi-Fi 用移动数据播同一个视频，再看。
- **应该看到**：Wi-Fi 下 720P，移动数据下 360P。
- **注意**：开了 VPN 或者系统识别不出网络类型时，会按「跟随默认」走，这时两边一样是正常的。
- **AI 判不了**：要真的切换网络（`svc wifi disable` 是设备级动作，且切换后要重连、要等系统上报新网络类型）。
  AI 只能先用 `get play_qn_wifi` / `play_qn_mobile` 确认两个值确实不同（这一半已归 T06），切换后的起播清晰度必须人看。

### T29 蓝牙耳机能切下一条

- **怎么做**：连蓝牙耳机 → 播放（最好是有连播队列的多 P 视频/合集）→ 按耳机上的「下一首」。
- **应该看到**：按连播队列切到下一条；按「上一首」回到上一条。
- **注意**：只有一条视频时按了没反应是正常的。
- **AI 判不了**：要有配好对的蓝牙耳机并按物理按键。模拟 `KEYCODE_MEDIA_NEXT` 只能证明代码回调能跑，证明不了耳机那条链路。

### T30 别的 App 抢声音时会暂停

- **怎么做**：正在播放 → 用另一台手机给自己打电话（或打开别的音乐 App 播放）。
- **应该看到**：我们的播放自动暂停。
- **然后**：电话挂断 / 别的 App 停掉之后，**不会自动接着播**，需要手动点一下播放——这是故意的设计，不是 bug。
- **AI 判不了**：需要第二台设备打电话，或装一个会抢音频焦点的 App。这是端到端行为，AI 造不出对端。

### T31 直播弹幕停留更久

- **怎么做**：先在 设置 → 播放器 → 长按「内置播放器」里，把「直播弹幕停留倍率」调成 3.0x → 回主菜单进一个直播间，看弹幕。
- **应该看到**：弹幕在屏幕上待的时间明显变长（默认 2.0x）。调回 1.0x 会更快。
- **注意**：这个只影响直播，不影响录播的「弹幕速度」。
- **AI 半自动**：`get player_live_danmaku_duration_factor` 应等于设定值（默认 `2.0`，改成 3.0 后就是 `3.0`），
  另可 `get player_danmaku_speed` 确认录播的「弹幕速度」没被一起改掉（键名来源
  `app/src/main/java/com/RobinNotBad/BiliClient/player/LiveDanmakuFactorPolicy.kt:19`）。
  「在屏幕上真的待更久」是画面，只能人看。

### T32 长按后上下划切视频

- **怎么做**：播放一个有多 P 或合集队列的视频 → 手指长按画面（会进入倍速）→ **保持长按**向上划。
- **应该看到**：切到下一条；向下划回到上一条。
- **不算 bug**：只有一条视频时划了没反应；手指横向偏移太大时不会切（怕和横滑调进度打架）。
- **AI 半自动**：`get player_longpress_switch` 应为 `true`；长按用 `input motionevent DOWN` → 睡 1 秒 → 带位移再 `UP`
  （长按手势不能直接用 `input swipe`），切没切看 `连播队列` 标签日志与 `top` 是否仍是播放器页但 `aid` 变了。
  「跟手不跟手」要人判。

### T33 长按倍速提示能变大变小

- **怎么做**：设置里把「长按倍速提示尺寸」设成 150% → 回播放页长按画面。
- **应该看到**：长按时出现的「x 3.0」提示明显变大；设成 80% 会变小。
- **AI 判不了**：「明显变大」是画面尺寸对比。AI 只能 `get player_longpress_hint_scale` 验值写进去了（=150 / =80），
  看不到提示框实际画多大。

### T34 老设备自动降档（可选，只有低端手表要测）

- **怎么做**：找一台配置较低的手表，**不要手动设清晰度**，直接播一个视频。
- **应该看到**：起播清晰度比较保守（低端机 360P 左右），同屏弹幕行数也更少，但播放更流畅。
- **注意**：如果你之前手动设过清晰度，会以你设的为准——这是设计。
- **AI 判不了**：要有低端真机。「流畅」是手感。

## 已知限制（测了「不对劲」也不算 bug）

1. **从主菜单「继续播放」进去时，「下一个」可能不能用**：这条路进播放器时播放列表还没加载完，队列会被丢掉。想切下一条请从视频页正常进入。这是已知项，本轮没修。
2. **历史搜索只搜「已加载的」**：翻得越深搜得越多，但不可能搜到没加载过的记录。
3. **「全部收藏」可能有重复**：同一个视频在多个收藏夹里就会重复出现。
4. **未登录不记进度**：不登录也能看，但观看进度和「继续播放」不会保存（服务端没记录）。
5. **直播清晰度不跟 Wi-Fi/移动数据分档**：直播间清晰度还是走它自己那套。
6. **背景图第一次显示可能慢半拍**：老设备上第一次解码要几百毫秒，属正常。
7. **大图放到最大有点糊**：长图是分块加载的，边缘会降清晰度省内存。
8. **新设置项对老用户不会自动变**：比如片头片尾，以前关着的升级后还是关着（会自动迁移成「关闭」），需要自己打开。

## 发现问题怎么报

一条好的问题描述包含五样东西，缺一样开发就得回来问：

1. **设备**：什么手表/手机、系统版本（设置 → 关于 里能看到）。
2. **App 版本**：26.11.06（测试版）。
3. **你做了什么**：按顺序写，比如「设置→播放器→长按内置播放器→点本人弹幕边框→退出→进视频」。
4. **你看到什么**：原话，比如「开关点了没变」「直接退回主菜单」「卡了 5 秒」。
5. **你本来期望什么**：对照本手册里那条「应该看到」。

有截图或录屏最好附上。**别只说「不行」**，那样没法查。
