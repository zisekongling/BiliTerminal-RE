为什么这么改（一句话版）

  • 两条实色灰带把画面切三截 → 换成上下渐变遮罩，画面连成一片。
  • 图标直接压在画面上 → 统一30dp 玻璃格（10dp 圆角 + 1dp 亮边），亮画面也看得清。
  • 播放键 32×37 比旁边 48dp 格更小 → 改成 40dp 主色圆，成为唯一视觉锚点。
  • 时间/在线人数挤在灰带上方一行 → 内嵌进进度行两端，省掉一行、贴边也修了。
  • 弹层是 1dp 粉线描边的实心卡 → 换 玻璃卡 + 低透明度亮边，与全站 GlassStyle 同源。

圆屏

新稿 · 圆屏（player_ui_round）
按弦宽收边：顶栏只剩返回 + 标题，底栏上移 14dp 收到 4 格
圆屏规则
  • 圆屏没有「固定安全边距」，只有弦宽：半径 116.5dp 的圆，高度 y 处的可用宽度 = 2·√(116.5² − (116.5−y)²)。竖直居中的左右两列吃满 233dp，20dp 内缩够用；越贴上下边越窄，所以「统一内缩一个值」在圆屏是错的。
  • 实测弦宽：y=16dp（顶栏中心）118dp · y=38dp 172dp · y=中部（两列）233dp · 底栏按钮行（距底 38dp）172dp · 底栏下沿（距底 14dp）只剩 110dp。顶栏因此只留 [返回 26][gap 6][标题 ≤85]，电量与时钟在圆屏隐藏；左右两列仍 20dp 内缩。
  • 方屏标题 = 233 − 6 − 26 − 6 − 26(电量) − 20(时钟) − 12 ≈ 137dp；圆屏 85dp，超出走 marquee（不是省略号——现状 MarqueeTextView 本来就是滚动的）。
  • 底栏必须内缩：60dp 高的底栏贴底时，它的底边正好落在圆的最低点（弦宽 = 0），两端的按钮一定被裁。做法是底栏整体上移 14dp，按钮行中心到圆心 78.5dp，弦宽 ≈172dp；4 格（清晰度 / 倍速 / 播放 / 分P）实测宽 141dp 放得下，第 5 格（组）在圆屏隐藏、改从右列进。

关键状态

同一套样式下的 7 个状态，全部由 CSS 状态类驱动（.st-paused / .st-locked / .st-quality …），不是另画一套。

为什么现在看起来丑

问题证据（行号 / 色值）后果
两条实色灰带 activity_player.xml:158 与 :203，android:background="#348A8A8A" 20% 中性灰横贯全宽、贴边、无圆角 —— 压在亮画面上是一层脏白膜，压在暗画面上是一条灰砖，画面被切成三截。
颜色不跟主题 ColorScheme 为每套主题都定义了 PLAYER_CONTROL_BG=0x33000000 / PLAYER_PROGRESS_FILL，播放器 XML 却写死 #348A8A8A 切到知乎蓝 / 爱奇艺绿主题时，只有进度条填充跟着变，底栏和顶栏还是那层灰 —— 半套主题。
图标裸压画面 button_pool：48dp 格 + 8~10dp padding，没有背景、没有描边 白色图标落在亮画面（雪景、纯白背景）上直接消失；左右两列尤其明显。
贴边的 11sp 文字 :131-152，text_progress / text_online 都是 match_parent，只有 2dp 内边距、alpha=0.8 两块全宽 TextView 叠在同一行靠 gravity 分左右；文字贴屏幕边缘，且颜色落在灰带上，对比度不够。
主按钮反而最小 :292-302，播放键 32dp × 37dp，夹在一排 48dp 格里 唯一的「动作」按钮视觉重量最低，一排图标里找不到落点。注释记录过「加内边距就被报变小」，说明这里一直是靠手感调、缺规则。
三种容器底 background_card=#24242E + 1dp #FF6699 描边；组展开条 = #80242424 + 2dp #cc262626；弹窗遮罩 #70000000 手表小屏上那圈 1dp 粉线就是「一圈廉价粉边」；加上组展开条的双层灰，同一个播放页里有三套容器语言。
圆屏靠代码打补丁 :325 right_control 只有 marginEnd=4dp；player_ui_round 分支在 PlayerActivity.kt:3324/:5440 4dp 边缘在圆形裁切下会切掉图标一角；安全区散落在代码里，没有一个统一常量。

落地路径（四步，每步可独立验证）

  1. 只换皮，不动结构：把 :158 与 :203 的 #348A8A8A 换成两个 shape 渐变 drawable（新增 player_scrim_top.xml / player_scrim_bottom.xml），字号与尺寸一行不改。验证：assembleDebug + 方屏/圆屏各看一眼。
  2. 按钮玻璃化：给 button_pool 里 27 个按钮统一挂 GlassStyle.choiceBackground()（PlayerButtonSlots 搬按钮时顺手设置，等价于 PlayerActivity.kt:8653 已经在做的事），播放键单独做 player_play_button.xml（40dp 圆 + 渐变）。
  3. 进度行重排：text_progress / text_online 从独立行改成进度条两端内嵌（涉及 updateUI 里的字符串拼接，改成「已播 / 总长」两段），底栏高度 60dp 固定下来。
  4. 弹层与圆屏：把 background_card.xml 的 1dp 粉描边换成低 alpha 亮边（会同时影响全 app 的卡片，要一起看效果）；圆屏不能只抽一个 inset —— 松手是三种值（左右 20dp / 顶栏 58dp / 底栏 bottom 14dp），建议抽 dimen/player_inset_side/top/bottom 三个，在 applyRoundLayout() 里按 player_ui_round 一次性覆盖，替换代码里散着的 4dp。
风险：background_card.xml 是全 app 共用的卡片底，第 4 步改的是它而不是播放器私有 drawable —— 要么另建 player_card.xml 只给播放器用，要么接受全站一起变。建议另建。
不变量（本稿一件都没动）：手势（单击显隐 / 双击播放暂停 / 双击两侧快进 / 横滑调进度 / 长按 3 倍速 / 双指缩放）、player_ui_layout 的存储格式与 5/5/3/3 容量、27 个按钮的 key、进度条 20dp 热区、字幕 marginBottom=76dp。

需要你定的三件事

  1. 底栏默认布局要不要按建议重排（音量 ± 降级进组、倍速上底栏）？现状也能套新皮。
  2. 播放键颜色：主色渐变圆（本稿，粉点作锚点）还是白底圆 + 深色三角（更克制）？
  3. 卡片描边：播放器私有新 drawable（推荐，只影响播放器）还是顺手把全站 background_card 一起换成玻璃口径？
