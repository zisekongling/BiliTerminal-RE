# 播放器页面重设计 v1（待评审）

- 日期：2026-11-18
- 状态：**只有设计稿，没有改任何代码**
- 可视化稿：[`docs/design/player-redesign-v1.html`](../design/player-redesign-v1.html)（单文件，浏览器直接打开；左边是现状 1:1 复刻，右边是新稿，带 10 个状态开关）
- 依据：`app/src/main/res/layout/activity_player.xml`（1305 行，行号按本轮 HEAD 核对）、`activity/player/PlayerActivity.kt`、`player/PlayerButtonSlots.kt`、`player/PlayerButtons.kt`、`ui/appearance/GlassStyle.kt`、`ui/appearance/ColorScheme.kt`

## 1. 一句话结论

播放器是「播放器自己的一套皮肤」：两条 `#348A8A8A` 实心灰带 + 直接压在画面上的白色图标，全站其它页早在 26.11 就换成了玻璃质感（`GlassStyle`）。把这两样换掉、把时序信息并进进度行、把主按钮做成唯一视觉锚点，观感就回来了——**不改手势、不改按钮槽位格式、不改任何功能**。

## 2. 现在丑在哪（每条都能指到行号）

| 问题 | 证据 | 后果 |
| --- | --- | --- |
| 两条实心灰带 | `activity_player.xml:158` / `:203`，`android:background="#348A8A8A"` | 20% 中性灰铺满全宽、贴边、无圆角，压在画面上就是一层脏白膜，把画面切成三截 |
| 颜色不跟主题 | `ColorScheme` 为每套主题都定义了 `PLAYER_CONTROL_BG` / `PLAYER_PROGRESS_FILL`，XML 却写死 `#348A8A8A` | 切到知乎蓝 / 爱奇艺绿时只有进度条填充跟着变，两条灰带不动——半套主题 |
| 图标裸压画面 | `button_pool`：48dp 格 + 8~10dp padding，无背景、无描边 | 白色图标落在亮画面（雪景、纯白背景）上直接消失；左右两列尤其明显 |
| 贴边的 11sp 文字 | `:131-152`，`text_progress` / `text_online` 都是 `match_parent`，只有 2dp 内边距、`alpha=0.8` | 两块全宽 TextView 叠在同一行，文字贴屏幕边缘；颜色落在灰带上，对比度不够 |
| 主按钮反而最小 | `:292-302`，播放键 `32dp × 37dp`，夹在一排 48dp 格里 | 唯一的「动作」按钮视觉重量最低，一排图标里找不到落点；注释记录过「加内边距就被报变小」 |
| 三种容器底 | `background_card` = `#24242E` + 1dp `#FF6699` 描边；组展开条 = `#80242424` + 2dp `#cc262626`；弹窗遮罩 `#70000000` | 同一播放页有三套容器语言：硬边卡、双层灰、纯遮罩 |
| 圆屏靠代码打补丁 | `:325` `right_control` 只有 `marginEnd=4dp`；`player_ui_round` 分支散在 `PlayerActivity.kt:3324` / `:5440` | 4dp 在圆形裁切下会切掉图标一角；安全区散落在代码里，没有统一常量 |

## 3. 设计口径

### 3.1 令牌（全部从 `ColorScheme` / `GlassStyle` 派生，不新增硬编码颜色）

| 用途 | 值 | 来源 |
| --- | --- | --- |
| 顶部遮罩 | `linear-gradient(180deg, rgba(0,0,0,.62), rgba(0,0,0,.30) 58%, transparent)`，高 58dp | 纯黑渐变，不引入中性灰；任何画面上都只「压暗」不「上色」 |
| 底部遮罩 | `linear-gradient(0deg, rgba(0,0,0,.80), rgba(0,0,0,.40) 52%, transparent)`，高 96dp | 底栏 60dp + 36dp 过渡 |
| 玻璃格 | `rgba(38,38,38,.72)` + 1px `rgba(235,224,226,.14)` | = `GlassStyle.palette()` 的 `card` / `stroke`（终端卡 `#262626` 的 72%） |
| 激活态 | 底 `rgba(255,102,153,.18)`、边 `rgba(255,102,153,.55)`、图标 `#FF8CB0` | = `GlassStyle.choiceBackground(selected=true)` |
| 主色 / 浅主色 | `#FF6699` / `#FF8CB0` | `ColorScheme.PRIMARY` / `PRIMARY_LIGHT` |
| 文字 | 主 `#EBE0E2`、次 `rgba(235,224,226,.72)` | `TEXT_PRIMARY`；时间用 tabular-nums |
| 轨道 / 缓冲 / 弹幕热力 | `rgba(255,255,255,.16)` / `.30` / `.26` | 沿用 `PLAYER_PROGRESS_BG` 的「白 + 低 alpha」思路 |
| 圆角 | 按钮 10dp / 胶囊条 17dp / 卡片 14dp / 轨道 2dp / 播放键 50% | 比现状 6dp 大一档，仍小于 `card_round_large`=12dp 的「卡片」口径 |

> **不做实时模糊**：手表上 `RenderEffect`/毛玻璃要 API 31，本机 `minSdk 19`，所以「玻璃」只用「近不透明底 + 1px 亮边 + 阴影」表达层次，不用 backdrop blur。卡片一律 `elevation=0`（半透明底透阴影会出脏边，见 `GlassStyle` 注释），阴影只出现在弹层这种「浮起来的东西」上。

### 3.3 默认布局（建议，可原样保留现状）

- 现状：左 `[锁定][倍速]` / 右 `[弹幕][旋转][组×11]` / 底 `[清晰度][音量-] 播放 [音量+] [分P]`
- 建议：左 `[锁定][睡眠定时]` / 右 `[弹幕][旋转][组]` / 底 `[清晰度][倍速] 播放 [分P][组]`
- 理由【推测】：手表有实体音量键与上下划手势，音量 ± 占着底栏最贵的两个位置；倍速是「看的时候会调」的，应该在拇指区。

## 4. 圆屏：没有固定安全边距，只有弦宽

【事实】`rebili_watch466`：466×466 @ density 320 → 233×233dp，`circular=true`，半径 116.5dp。任意距顶 `y` 处的可用宽度 = `2·√(116.5² − (116.5−y)²)`。

| 位置 | 弦宽 |
| --- | --- |
| y=16dp（顶栏中心） | 118dp |
| y=38dp（顶栏下沿） | 172dp |
| y=中部（左右两列） | 233dp |
| 距底 38dp（底栏按钮行） | 172dp |
| 距底 14dp（底栏下沿） | 110dp |

结论：

- **顶栏**在圆屏只留 `[返回 26][gap 6][标题 ≤85]`，电量与时钟隐藏；方屏照旧。
- **底栏**整体上移 14dp：按钮行 4 格（清晰度 / 倍速 / 播放 / 分P）实测宽 141dp，放得下；第 5 格（组）在圆屏隐藏，改从右列进。
- **左右两列**仍 20dp 内缩（该高度弦宽最大）；弹层左右收到 12dp。
- 代码侧不要只抽一个 `inset`：至少三个值（左右 20 / 顶栏 58 / 底栏 bottom 14），统一在 `applyRoundLayout()` 里按 `player_ui_round` 覆盖。

> 注：现状 `player_ui_round` 分支散在 `PlayerActivity.kt:3324` 与 `:5440`，本轮只读代码未见集中封装【推测：需要按上面三点重排】。

## 5. 落地路径（四步，每步都能独立验证）

1. **只换皮，不动结构**：`:158` 与 `:203` 的 `#348A8A8A` 换成两个 shape 渐变 drawable（新增 `player_scrim_top.xml` / `player_scrim_bottom.xml`），字号与尺寸一行不改。验证：`assembleDebug` + 方屏/圆屏各看一眼（L2 人工）。
2. **按钮玻璃化**：给 `button_pool` 里 27 个按钮统一挂 `GlassStyle.choiceBackground()`（在 `PlayerButtonSlots` 搬按钮时顺手设置，等价于 `PlayerActivity.kt:8653` 已经在做的那件事）；播放键单独做 `player_play_button.xml`（40dp 圆 + 渐变）。验证：日志里 27 个 key 都拿到背景（L1），观感 L2。
3. **进度行重排**：`text_progress` / `text_online` 从独立行改为内嵌进度条两端（涉及 `updateUI` 里的字符串拼接，改成「已播 / 剩余」两段），底栏高度 60dp 定死。验证：L1 读控件树文字确认两段时间都在，L2 看是否压住进度。
4. **弹层与圆屏**：`background_card.xml` 的 1dp 粉描边换低 alpha 亮边（**会同时影响全 app 的卡片**，要一起看效果）；圆屏三个 inset 抽 dimen 并集中覆盖。验证：L2（全站卡片观感 + 圆屏四角）。

## 6. 风险与不变量

- **风险**：`background_card.xml` 是全 app 共用的卡片底，第 4 步改它等于改全站。推荐另建 `player_card.xml` 只给播放器用；若选「全站一起变」，得单独一轮回归。
- **不变量（本稿一件都没动）**：手势全套（单击显隐 / 双击暂停 / 双击两侧快进快退 / 横滑调进度 / 长按 3 倍速 / 双指缩放）、`player_ui_layout` 的存储格式与 5/5/3/3 容量、27 个按钮 key、进度条 20dp 热区、字幕 `marginBottom=76dp`。
- **尺寸纪律**：播放键与底栏高度是被用户反复校准过的敏感区（26.11.07 放热区导致底栏 59→94dp 被报「底栏拉粗」、26.11.08 整批回退）。本稿把播放键从 32×37 放大到 40dp 属于**观感改动，需要用户拍板**，不能默默改。

## 7. 需要用户定的三件事

1. 底栏默认布局要不要按建议重排（音量 ± 降级进组、倍速上底栏）？现状也能套新皮。
2. 播放键颜色：主色渐变圆（本稿，粉点作锚点）还是白底圆 + 深色三角（更克制）？
3. 卡片描边：播放器私有新 drawable（推荐，只影响播放器）还是顺手把全站 `background_card` 一起换成玻璃口径？

## 8. 验证方式（按 `docs/agents/testing.md`）

- **L0**：`./gradlew.bat :app:assembleDebug` + 相关单测；纯 drawable / 布局改动也必须过。
- **L1**：Debug 包起播放页，读控件树文字确认三处改动（时间两段、按钮背景非空、圆屏 inset 生效），写进交接单。
- **L2（只能人工）**：亮画面/暗画面各看一遍图标可读性、拖动进度时的拇指手感、锁定遮罩观感、圆屏四角裁切。
