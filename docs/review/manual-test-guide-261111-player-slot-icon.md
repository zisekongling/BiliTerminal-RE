> L0 已过：`:app:assembleDebug` BUILD SUCCESSFUL；`:app:testStandardDebugUnitTest --rerun` 220 suites / 2385 tests / 0 失败 0 错误（26.11.11 本机实测）。
> 预计 10 分钟；**不需要登录**，任意能播的视频即可（短视频页不受影响，不用看）。

## 这次改的是什么（先理解再看画面）

播放器的按钮是「槽位」渲染的：同一份按钮被放进左列 / 右列 / 底部左 / 底部右四个区之一。**同一个按钮如果在两份布局里都出现，第二份是「影子」**——影子每秒 2.5 次（400ms 一轮）从真身抄图标、显隐、点击。

用户截图里的坏格子是「弹幕开关」：它默认在右列，用户又把它加进了底部左区，于是底部是真身、右列是影子。旧代码让**影子和真身共用同一个 `Drawable` 实例**，而 `Drawable` 只有一组 bounds —— 谁最后写谁说了算。真身被右列 28dp 格的 48px bounds 覆盖后，在底部 32×37 的格子里就画成「小一圈 + 贴左上角」。本次改成：影子拿一份复制出来的 `Drawable`；同时把四区图标的 `scaleType` 统一成等比居中（原来按钮池里有两批：清晰度/音量/分P 是 `fitCenter`，弹幕/字幕/循环那批是 `fitXY`，`fitXY` 在 32×37 的格子里会把方图标竖向拉长 1.19 倍）。

所以下面要看两件事：**大小对得上**（H25）和**别的东西没被带坏**（H26）。

## H25 同一个按钮放两处时，底部那一格要和同行一致

前置：设置 → 视频播放器 → 界面（`SettingPlayerUiActivity`）。默认布局是「左列：锁定 + 倍速」「右列：弹幕 + 旋转 + 9 格组」「底部左：清晰度 + 音量-」「底部右：音量+ + 分P」。

1. 把「弹幕开关」加进**底部左区**，**同时保留它在右列**（新增一份，不要从右列删）。这是复现用户截图的状态。
2. 随便播一个视频，等画面出来，看底部按钮行（播放暂停圆盘左右两侧那一排）：
   - [ ] 底部那一格弹幕图标**大小**与同行的清晰度、音量-、音量+、分P 一致（改前它会明显小一圈、像缩在格子左上角）
   - [ ] 它的**中心**落在同一行图标的中线上（改前它会比同行高约 4~5dp）
3. 在播放页停留 **10 秒以上**再截一张图对比：
   - [ ] 底部这一格没有变化（影子同步定时器每 400ms 跑一轮，如果还是共用 Drawable，跑几十轮后会更明显）
   - [ ] 右列那一份（影子）也是正常大小、没有反过来被底部那份挤小
4. 换几个位置再各看一眼，每次都要回播放页（`onResume` 重读布局）：
   - [ ] 只放右列（默认布局）——与改前一模一样
   - [ ] 只放底部（把右列的弹幕开关删掉）——正常
   - [ ] 底部左 + 底部右各放一份（三处同时存在）——三处都正常

**判据**：只要还有一格比同行小或偏上，说明还有第三处覆盖 bounds 的地方（下一步该查 `PlayerActivity` 里对该按钮做的任何 `setImageDrawable` / `setImageResource`，以及 `VectorImageView` 之外的 `ImageView` 实例）。先截图对照测量再改，不要凭感觉调尺寸。

## H26 回归：其它按钮与收纳格没被带坏

`scaleType` 被统一成 `FIT_CENTER` 后，理论上「原来就是 fitCenter 的那批」观感不变，**只有原来 fitXY 的那批会变（变正确）**；但收纳格（更多按钮）与文字按钮走的是另一条分支，必须单独看一眼。

1. 默认布局下看右列的「更多」收纳格（三点 / 展开图标）：
   - [ ] 图标仍是**方形**、大小与旁边的弹幕、旋转一致（改前它被显式设成 `fitXY`，在 32×37 格里是扁的）
   - [ ] 点它展开同侧那条竖排的 9 个按钮，每个都是方形、间距均匀；再点一次收起，格子回到「更多」图标
2. 逐个把下列按钮放进底部区看一眼（它们原本属于 fitXY 那批，是本次行为变化最大的一组）：
   - [ ] 字幕、循环、音频模式、自动连播、看点、视频信息、跳转时间、队列模式、发送弹幕 —— 全部方形、和清晰度 / 音量图标一样大
   - [ ] 「倍数」（文字按钮）仍是文字、没有被拉成长条，点击能弹倍速选择
   - [ ] 「视频信息」若同样是文字按钮，字号与改前一致
3. 播放控制回归（不要只看图标）：
   - [ ] 底部播放 / 暂停圆盘点一下能暂停、再点能继续（圆盘没被裁掉一块）
   - [ ] 清晰度、音量-、音量+、分P 四个原有按钮点击热区仍是整格（点格子边缘也命中）
   - [ ] 锁定按钮：锁定后按钮搬到屏幕左边缘、解锁后回到原位，图标大小不变
4. 圆屏适配开 / 关各看一遍（圆屏开启时 `bottom_buttons` 会加屏宽 3% 的内边距）：
   - [ ] 两种情况按钮行都居中、没有被内边距推歪

**判据**：只要有一个图标变成「非方形」（明显扁或明显长），说明该按钮走了别的渲染分支、没经过 `cellParams` 的 `scaleType` 统一，需单独定位；文字按钮被裁切则是 `cellParams` 的 `WRAP_CONTENT × h` 分支被误改。
