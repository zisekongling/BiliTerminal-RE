# 安全与清单硬约定

> 常驻红线摘要见 `AGENTS.md`；本册是动清单、网络域名、备份、调试入口时的完整约束（26.09.13 起）。改这些文件前逐条过一遍。

- **新增 Activity 一律 `android:exported="false"`**；只有确实要被外部应用/系统拉起（LAUNCHER、外链分享、被当作「打开方式」）才开 `true`，并说明理由。**Release 包**收官后全应用仅 `SplashActivity`、`GetIntentActivity` 与 `ExternalVideoActivity` 导出（最后一个 26.11.17 起：作为系统视频打开方式接 `ACTION_VIEW`/`ACTION_SEND`，只认 `content://`/`file://` 且 `video/*`，不接 http(s)）；Debug 包另有两个仅供测试的导出组件（`TestActivity`、`debug/DebugBridge`），它们只存在于 debug 源集，不进发布包。
- **只走 https**。新的自建接口不得用 `http://`；明文域名白名单在 `res/xml/network_security_config.xml`，默认禁止明文，只放行 `bilibili.com`/`hdslb.com`/`bilivideo.com`/`afdiancdn.com`。往白名单加域名要写原因。
- **唯一有意的明文请求是 `api/ServerTimeApi`**（26.10.27）：设备时间错了时 https 全部失败，只能走 http 问服务器时间来给提示。它必须用独立客户端、**不带 Cookie**、不跟随跳转，结果**只用于显示**，不得参与证书校验或拿来「修正」时间放行连接。别照着它另写明文请求。
- **内置根证书只追加、不放宽**（26.10.26）：`util/ExtraTrust.java` 把 `res/raw/extra_ca_roots.pem`（目前只有 ISRG Root X1 / X2，给 Android 7.1 及以下补上 Let's Encrypt 的根）追加到系统信任锚上，**只给 `UpdateManager` 的客户端用**；带登录 Cookie 的 `NetWorkUtil` 主客户端保持系统默认。往 PEM 里加证书必须是公开 CA 的**根证书**，并在类注释里写明来源和 SHA-256；绝不允许为了「连得上」退回 trust-all 或关掉主机名校验。
- **`android:allowBackup` 保持 `false`**，登录 Cookie 存于 SharedPreferences，绝不允许随备份/迁移外流。`:brotlij` 自带 `allowBackup="true"`，故主清单必须保留 `tools:replace="android:allowBackup"`（删了会清单合并失败）。
- **调试页只进 Debug 包**。`TestActivity` 是范例：类留在 `src/main`，清单声明在 `app/src/debug/AndroidManifest.xml`，入口用**编译期常量** `BuildConfig.DEBUG` 包住（不是 `BiliTerminal.isDebugBuild()` 这种运行期判断），这样 R8 才能在 release 折叠分支并 strip 掉整个类。
- **Debug 包的外部可达组件必须挂 `android:permission="android.permission.DUMP"`**（26.10.14 起）。给 agent 用的调试入口必然要 `exported="true"`（adb shell 是 uid 2000、非 root，拉不起非导出组件），但**裸导出等于把登录态送人**——DUMP 是签名级权限，普通第三方应用拿不到，而 adb shell 持有（`dumpsys` 就靠它）、本应用自己天然放行。类与清单一律放 `app/src/debug/`，安全边界是「发布包不含它」，不是「它自己判断是不是 debug」。用法与坑见 `docs/review/agent-test-guide.md`。**26.11.19 起 debug 源集把主清单里其余 117 个非导出页面也一并导出**（同样挂 DUMP），agent 可以直接 `adb shell am start -n <包>/.某个页` 冷启动到任意页面；这份清单只在 `app/src/debug/`，Debug 合并产物因此是「121 个导出 / 118 个带 DUMP」，Release 合并产物仍是「3 个导出 / 0 个 DUMP」。两边由 `app/src/test/java/com/RobinNotBad/BiliClient/DebugActivityExportTest.kt` 守住：主清单新增页面忘了补进 debug 清单会红，给已导出的 3 个页面挂 DUMP 也会红。
- **调试能力的开关必须「改完即生效」**。日志级别、落盘、HTTP 追踪统一由 `BiliTerminal.applyLogSwitches()` 一处落地（读 `SettingsKeys.DEV_*`），改完开关要立刻调它——别让用户/agent 为了生效去重启应用，自动化流程里「重启」意味着上下文丢失加一轮等待。`Agent 测试模式`（`DEV_AGENT_MODE`）是这套的总开关，Release 下因 `BuildConfig.DEBUG` 是编译期常量而被整体折叠。
- **本册前三条（导出面 / `allowBackup` / 明文白名单）已有可执行的守门**（26.11.22 起）：`app/src/test/java/com/RobinNotBad/BiliClient/SecurityRedLineTest.kt` 断言主清单导出集合恰为那 3 个页面、`allowBackup="false"` 且保留 `tools:replace`、`base-config` 禁明文、放行域名集合恰为上面 4 个。它和 `DebugActivityExportTest` 的分工是「验是谁」与「验数量」——数量相等时把某个导出页换成另一个仍能作弊通过，所以两边都要在。要动这些值，先改本册并写理由，再同步改测试。
