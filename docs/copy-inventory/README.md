## 三、条目的统一格式

每份清单都是同一套结构，一条长这样：

```markdown
### X-001 一句话标题

- **位置**：`仓库相对路径:行号`（可附 `R.string.xxx`）
- **出现在哪**：导航路径或触发动作，写清载体（页面标题/按钮/Toast/弹窗/通知栏…）
- **用途**：一句话讲清这段文案要达成什么
- **原文**：

> 逐字照抄，多行用连续 > 行

- **改写**：

> 已预填与原文同一句，你在这里改出一版新的
```

成组的短标签（页面标题、`hint_*`、`btn_*`）用表格，最后一列同样是留给你的「改写」空位。

**推荐的逐条改写流程**（2026-10-19 起，「改写」里已经预填了原文）：

1. 打开一份清单，从第一条开始；
2. 读「出现在哪 / 用途」，判断这句话要不要改（不想改就跳过）；
3. 直接把「改写」那份改成新文案，**原文那句留着别动**（它是核对与批量替换的锚点）；
4. 该条标题后加 `〔待落地〕`，表示「已定稿，等搬进代码」；
5. 写完告诉 Lead，由它成批搬进源码（位置/双真相/红线清单里都写着，配合细则见 [GUIDE.md](GUIDE.md) 第十一节）。

想自己动手改代码也行：按「位置」打开源码把新文案落进去，再对照该条下方的「双真相」提示把别处一起改掉（见第五节）。

## 四、改之前必须知道的约束

### 4.1 文案的落点规则（本仓库的既有事实）

- **设置页及相关字符串放在 `app/src/main/res/values/strings.xml`**（`desc_*` 是惯例），其余文案**在代码或布局里硬编码中文**。
- 页面标题有**四套写法**，只改一处会白改或闪一下：布局里的 `android:text`、代码里的 `setPageName("…")`、`pageName.text = "…"`、`title.text = "…"`。详见 05 第〇、一节。
- `strings.xml` 里以 `#` 开头的行（如 `:16`/`:297`/`:349`/`:365`/`:626`）**不是 XML 注释语法**，是被解析器忽略的纯文本行——改文案时别照着它的风格加注释。

### 4.2 三处互相引用的对外承诺（改一处必须同步三处）

`about_to_uncle`（01 的 `A-028`）、`text_setup_introduction`（01 的 `A-030`）、`privacy_consent_message`（01 的 `A-036`）三处内容互相引用：
`strings.xml:562-566`、`api/TerminalApi.java:85-86`、`util/TelemetryReporter.kt:15` 三处注释都写明了这件事。改任一处必须同时改另两处，且 **`TerminalApi.PRIVACY_VERSION` 要 +1**，否则老用户不会重新看到隐私确认。

### 4.3 教程正文改了要升版本号

`TutorialStore.kt:14` 用 `readVersion(id) >= tutorial.version` 判断是否已读。**只改正文不升 `Tutorials.kt` 里的 `version`，老用户永远看不到新版**。

### 4.4 更新日志有硬格式（自动化会读）

- `update_log_current` 首行必须是 `【YY.MM.DD 本次更新】`——`UpdateHistoryActivity.kt` 用正则 `\d{2}\.\d{2}\.\d{2}` 抠版本号；
- `update_history_log` 每组必须以 `## YYYY-MM-DD` 开头；
- `[分类]` 的首尾方括号会被加粗（`UpdateHistoryActivity.kt:202`），**必须保留**；
- 空 `<item></item>` 会被跳过；同名日期组整组丢弃；
- **发版时 `update_log_current` 会被整段搬进 `update_history_log`**（见 `.dsh/skills/rebili-version-release`），所以不能在里面留自定义占位行。

### 4.5 不该动的「文案」

- `tools:text` / `tools:visibility` 只在 Android Studio 预览生效，**不进 APK**；
- `cell_*.xml` 里绝大多数 `android:text` 是给预览看的示例值，运行时被 adapter 覆盖；
- 设计占位符（`标题标题…`、`文本文本文本`、`蔡徐坤`、`114514条`、`P1 标题`…）是作者随手填的梗。

以上三类分别在 05 的第〇、十三、十四节单列，**照抄原名不代表它们会显示给用户**。

## 五、「双真相」：同一句话的两处定义

05 第十五节（`U-260`）汇总了 **11 组**同一句话在多处独立定义的文案，改一处必漏，例如：

- 列表空态「啥都木有~」→ 代码一处（`RefreshListActivity.kt:25`）+ 4 个布局硬编码；
- 「没有更多了 / 正在加载…」→ `RefreshListActivity.kt:307`/`:308` 与 `RefreshMainActivity.kt:80`/`:81` 各一份；
- 音量显示 → 代码与布局共 3 个副本；
- 弹窗按钮「确定 / 取消 / 知道了」→ 布局 3 处 + `TerminalDialog.kt` 默认值；
- 「共1张图片」→ 4 个布局副本。

跑一遍 `grep` 比信任单点定义可靠。**改任何一句话之后，建议直接全仓搜一遍原文**。

## 六、按原文全仓复查的一句话（收尾用）

三处刻意的不一致，改写时可顺手统一，也可保留（都是有意的现状）：
