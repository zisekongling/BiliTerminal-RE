- 版本：`versionName 26.11.07` / 对应 commit `6591f05`（布局图片控件补无障碍描述 + 播放器控制键热区放大）；**H05 还验同批提交的「左列高度上限」修复**（26.11.08 验收发现的回归，提交 `2989652`）

## H01 读屏把播放器按钮念成中文名，而不是「按钮」

- **怎么做**：①设置 → 无障碍 → 打开 TalkBack（部分手表叫「屏幕阅读器」/「旁白」）；②主菜单进任意视频 → 播放 → 单指点一下画面让控制栏出来（约 4 秒不操作会自己收起，所以要边点边走）；③用读屏手势（单指上下左右滑动）逐个移焦点，把顶栏、底部按钮行、左右两列都走一遍，最后在某个键上双击试一下能不能激活。
- **应该看到**：焦点走到每个键时念出的是中文名字，而不是「按钮 / 图片」：清晰度、音量减、音量加、分P、发弹幕、字幕、循环播放、听视频、自动连播、看点、跳转时间（跳到指定时间）、连播队列、弹幕、旋转、播放与暂停、锁定播放画面（防止误触）、展开这组按钮（「更多」那个方块）。念完名字还会补一句「双击即可激活」；焦点顺序跟着画面走，不会在同一个键上打转。
- **不算 bug**：当前布局里没有的键（被你关掉或挪进「更多」组里）不该被念到；「播放与暂停」图标会变但名字不变；同一个按钮被你放了两处时两处都会念（影子按钮，点哪都生效）；把某键收进组里后，只有点开「展开这组按钮」才会出现它的焦点。
- **AI 断言**：`adb shell uiautomator dump /sdcard/ui.xml && adb pull /sdcard/ui.xml`，在 XML 里查 `content-desc`——播放页里非空的中文描述应有 10 个以上，且**不应**出现 `content-desc="按钮"` / `content-desc="图片"` 这类空描述（改造前这些键的 `content-desc` 是空串）。人判：念出来的名字顺不顺耳、顺序跟不跟画面。
- **预计**：3 分钟

## H02 读屏在列表页只念有用的信息，装饰图不出声

- **怎么做**：读屏开着回菜单 → 在「推荐」页往下滑两三屏；再进一个视频详情页看 UP 主区；再进「我的 → 关注」看关注列表；最后进任意视频看评论区。
- **应该看到**：视频卡念的是标题、UP 名、播放量这些文字，**不再逐个念「图片」**；UP 主头像念「查看用户主页」；评论区头像同样念「查看用户主页」；认证角标念「已认证」；行内的小箭头、分隔线、角标这类装饰图标**完全不念**，焦点也不会停在它们上面（滑一下直接跳到下一个有意义的元素）。
- **不算 bug**：视频卡的封面在列表里不念（它只是装饰，点卡片才播放）——这是刻意的；详情页封面另有「播放视频，长按查看封面大图」的描述；一张卡里的文字和头像会是两个焦点，所以过一张卡要滑两下。
- **AI 断言**：同一份 dump 里数 `content-desc="查看用户主页"` 的节点数量，应等于当前屏可见的头像数（列表里 0 个也正常——列表页头像在卡片内是装饰）；装饰图应带 `importantForAccessibility="no"`，因此不会出现在可聚焦节点里。人判：念得是否啰嗦、有没有漏念。
- **预计**：3 分钟

## H03 图标还是原来的大小，只有「能点中的范围」变大

- **怎么做**：手边有改造前的包（26.11.07 之前的任一包）最好：两个包都进同一个本地视频的播放页，暂停在同一帧，左右两列与底部行逐个对照看图标的大小与离屏幕边缘的距离。手边没有旧包也行，按下面「改造前的样子」核对：左右两列图标 28dp、贴着屏幕左右边缘、列内竖着排；底部图标 32×37dp、中间是播放键。
- **应该看到**：左右两列图标仍是 28dp，仍贴着屏幕边缘（放大的那圈向屏幕**内侧**扩，图标位置不动）；格子变宽后图标不跟着变胖、不变形、不模糊；底部行图标观感仍是 32×37dp，只是点得中的范围大了；「更多」那个方块图标还是方块，没有被拉成扁条。
- **不算 bug**：按钮少的时候，底部两侧的按钮会**紧贴中间的播放键**（两侧各用 weight 平分剩余宽度），与改造前「整行居中」的排布略有不同——这是为了让按钮多了不被裁掉；把小屏手表的右侧列放大后高度只到 48×29dp 左右，属已知限制。
- **AI 判不了**：dump 只能量到**格子**的 bounds（能断言底部按钮 44×44dp、进度条 48dp），量不到图标本身的像素；「看上去是不是一样大」只能人眼比。
- **预计**：2 分钟

## H04 热区手感：点图标外围的空白也能中，进度条更好拖

- **怎么做**：进播放页，控制栏出来后用手指（不要用指甲、不要戴手套）点底部按钮的**边缘**（离图标中心约 15～20dp 的地方），四个键各点一次；再按住进度条波形**上下约 10dp 的空白**左右拖；左右两列的图标也各点一次内侧空白；最后试点一次「发弹幕」。
- **应该看到**：点在图标外围的空白处也能触发（改造前必须点在图标上）；进度条上下各约 14dp 的空白都能拖动，拖的时候进度跟手、不会误触到上面的按钮；指尖稍偏一点不再「点了没反应」；误触明显变少。
- **不算 bug**：小屏手表右列 3 格的高度只有 48×29dp 左右（可用高度放不下 3×48dp），**高度没到 48 是已知限制**，宽度与图标位置是对的；进度条的可视波形高度仍是 20dp（上下各 14dp 是内边距，不是波形变粗）。
- **AI 断言**：`uiautomator dump` 量 `button_video` 的 bounds 应为 44×44dp、`videoprogress` 高度 48dp（2px=1dp 的 466×466@320dpi 屏）；「按下去到底有没有触发」只有人手上能判。
- **预计**：3 分钟

## H05 自定义布局：左列放 3 个及以上按键时，不压进度条、进度条还能拖（重点）

这一条是 26.11.08 验收抓到的回归，必须在真机上复现一次。

- **怎么做**：
  1. 「播放器界面」入口 26.11.09 已恢复（`cfb4f83d`）：从「设置 → 选择播放器 → 播放器界面」卡片进，或直接在设置搜索里搜「播放器界面」。下面的调试桥拉起方式仍然可用（省得翻菜单）：

     ```bash
     adb shell am broadcast -n com.RobinNotBad.BiliClient/com.RobinNotBad.BiliClient.debug.DebugBridge \
       --es token rebili-agent-bridge --es cmd start --es activity SettingPlayerUiActivity
     # 装的是共存版时包名要写 com.RobinNotBad.BiliClient.coexist（前后两处都改）
     # 返回 OK 只代表没抛异常，再用 --es cmd top 确认真的到了这一页
     ```

  2. 进页后找到「左列（N 格）」分组，点「＋ 加一个按钮」，连加到 **3 个及以上**（默认左列只有「锁定」和「倍速」两格；第 3 个挑「弹幕」或「旋转」都行），最好再试一次加到 5 格（左列上限）。
  3. 返回，进任意视频播放；点一下画面让控制栏出来；看左列与底部进度条的关系。
  4. 手指按住进度条左端慢慢拖到右端，再拖回来；重复两次。
- **应该看到**：左列 3 个（或 5 个）图标**变高但不会盖到进度条和底部按钮行**，也不压住顶栏；进度条照常能拖、跟手、不被左列的格子抢走触摸（改造前的回归表现是：左列格子按整窗高度放大，3 格就顶到进度条上，进度条左半段拖不动）；左列图标仍贴着屏幕左边、上下居中，与右侧列中线对齐。
- **不算 bug**：格子放不下时高度会回落到 28dp（改造前的尺寸）——这是刻意的兜底：宁可热区小，也不压住别的控件；右列还没布局时左列也保持 28dp。**但如果你真的看到压住进度条或拖不动进度条**，那就是本单要抓的问题。
- **AI 断言**：`adb shell uiautomator dump` 后取 `left_column_slots` 与 `videoprogress` 的 bounds，两个矩形**不应相交**（这一步 AI 能跑）；「图标挤不挤、看不看得清」要人判。
- **失败时交什么**：截图或录屏 + `adb shell uiautomator dump /sdcard/ui.xml` 的 XML + 你放在左列的键名与顺序 + 设备型号与屏幕分辨率。
- **预计**：5 分钟

## H06 小屏手表上四块区域不重叠、圆屏不切角

- **怎么做**：换到可用高度最小的那台手表（约 209dp）进播放页，控制栏出来后整体看一眼：顶栏、进度条、底部按钮行、左右两列有没有互相压住；圆屏机型再看四个角有没有被圆盘切掉（尤其底部行的两端）。
- **应该看到**：四块区域各自完整、互不重叠；底部行左右两端的按钮不贴到圆角上被切掉一半；左右列图标完整不出屏。
- **不算 bug**：圆屏边缘本就有装饰性留白；播放器不会像列表那样做「圆屏缩放」，图标贴边是设计。
- **AI 判不了**：这是屏幕形态 + 观感判断，方屏 AVD 替代不了真机圆屏。
- **预计**：2 分钟

## H07 底部按钮放满时横向滚动，不挤爆按钮行

- **怎么做**：回「播放器界面」（打开方式同 H05 第 1 步），给「底部左侧」和「底部右侧」各放到 3 格（这就是上限）；返回播放页，在底部行左半、右半各横滑一下，再点最边上那个键。
- **应该看到**：按钮少时紧贴中间的播放键；按钮多时**在自己的那半屏里横向滚动**，不会整行被屏幕裁掉、也不会压到播放键；滚到最边上的按钮仍点得中；横滑底部行时不会误触发播放器手势（左右滑调进度、上下滑调音量）。
- **不算 bug**：横向滚到尽头有轻微回弹；播放/暂停键固定居中、不可自定义（自定义的格位都在它两侧）。
- **AI 判不了**：滚动手感与「横滑会不会误触」只能真手判。
- **预计**：2 分钟
